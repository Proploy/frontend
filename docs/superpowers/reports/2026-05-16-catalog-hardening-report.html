Three-Layer Architecture

Backend service-apis (FastAPI) returns: count/results, semantic_query, short_description, avg_rating
↓ raw JSON
Contract catalog-contracts.ts Backend field names preserved exactly. No UI assumptions.
↓ mappers
View Model catalog-view-models.ts UI-friendly names: product_description, rating, reviews.
↓ hooks return view models
Hooks use-catalog-*.ts useCatalogProducts, useCatalogSearch, useCatalogCategories, useProductDetail
↓ view model data
UI components/pages SearchBar, products/page, product/[id]/page

Raw backend responses always pass through mappers before reaching UI pages or components. UI components never consume contract types directly.

Error Handling Contract

All errors are normalized to { ok: false, status, error: { code, message, retryAfter? } }.

Code Status UI behavior
CIRCUIT_OPEN 503 User-safe message + retry countdown. No auto-retry in hook.
AUTHENTICATION_ERROR 401 Public catalog does not expect auth — indicates misconfiguration.
NETWORK_ERROR 0 Browser could not reach service-apis. Show connection error.
NOT_CONFIGURED 503 NEXT_PUBLIC_SERVICE_APIS_URL not set. Console warning + error state.
INTERNAL_ERROR 500+ Generic "Something went wrong" — backend details never leaked to UI.

Implementation Guards

No raw contract types in UI
UI pages/components never import or consume catalog-contracts.ts types directly. All data passes through mappers.
Hooks call service-apis directly
Hooks call /catalog/* routes directly. They do not call /app/api/* proxy routes.
No mock fallback in production paths
If service-apis is unavailable, hooks return error states. No FALLBACK_PRODUCTS or placeholder data in migrated paths.
No auto-retry in hooks
Hooks expose error.retryAfter and refetch. UI decides whether/how to show retry controls.
App/api routes untouched
/app/api/* proxy routes remain as compatibility shims. Not deleted or refactored in this slice.
Backend field names preserved in contracts
Contract types mirror backend exactly: short_description, avg_rating, total_reviews, semantic_query, count/results.
